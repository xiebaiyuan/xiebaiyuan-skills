写给 agent 读的文档，目标是每次运行走同一条过程。中文表达按 `~/.config/magpie/library/instructions.md` 的「表达」一节写；结构按本文写。两边冲突时，措辞听 instructions.md，结构听本文。

## 写之前先定三件事

- 读者：agent。它没有你的上下文，只有这份文档。
- 分支：这份文档处理哪几种不同情形，每种走哪条路。
- 完成标准：每一步做到什么算完。

三件事答不出，先问用户，别开写。

## 指针（描述行、AGENTS.md 里的引用行）

指针是常驻上下文里的一行字，决定 agent 什么时候去读被指向的材料。措辞决定触发，目标文件不决定。

- 第一个词放最能触发的词。
- 一个分支一个触发词。同义词只留一个。
- 正文已经说了的身份信息，不在指针里重复。
- 必读材料挂在弱指针后面，先改指针措辞；改不动再把材料内联。
- 描述行用中文写触发场景，不写工作流摘要。

## 信息层级

从上到下三层，越上层 agent 越先用到：

1. 文件内的步骤：agent 按顺序做的事。
2. 文件内的参考：定义、规则、事实，按需查。同级并列的规则清单是正常形态。
3. 外挂参考：放进 `references/` 之类的文件，用指针触发才读。

判据：每个分支都要的内联，只有部分分支要的外挂。有步骤的文档里夹一大段参考，步骤会被淹掉，执行时漏不漏全靠运气。

同一概念的定义、规则、注意事项放在同一个标题下。文档过长（每行都有用也一样）就按分支或顺序拆，每条路径只带自己要的。

## 步骤与完成标准

每一步写完成标准：agent 凭它能判断「做完了」还是「没做完」。

- 标准要可判定。「理解清楚」不行；「每个改动的模型都列出来，逐个有结论」行。
- 标准要有要求量。「每条规则都应用过」逼出的工作量，大于「给出改动清单」。
- 最好的标准同时可检查、可穷尽。
- 步骤会提前收工：agent 看着后面还有步骤，就想赶紧结束手上这步。先把标准写锋利；确实模糊又观察到赶工，再用子代理或交接拆开，让后面的步骤不在视野里。同一上下文里内联调用拆不开。

## 用词

- 优先用模型预训练里已有的词当「引导词」（tight、red、tracer bullet、fog of war），全文重复这个词，不重复解释它的句子。自造词要先定义，定义花的字数就是成本。
- 三个形容词拼起来的描述，找一个词代替它。
- 用正面指令。写「每条注释一行」，不写「不要写长注释」。禁令只留给无法正面表述的硬边界，并且同一处附上正面目标。

## 修剪

- 一个意思只写一处。重复会抬高它在层级里的分量，改行为时也要改多处。
- 环境里查得到的事实（`package.json` 脚本、配置文件、目录结构、`--help` 输出）不抄进文档。只写查不到的：没成文的约定、选择的原因、没有配置会告诉你的坑。
- 逐行问相关性：这行还跟这份文档的任务有关吗？过时的、从没相关过的，删。
- 逐句找无效句：agent 默认就会做的事，写了不改变行为。整句删，不要抠字。判断依据是跑一遍文档看行为，不靠争论。引导词太弱同理，换更强的词（「认真」换「relentless」）。
- 只增不删会长成沉积层。每次加内容，同时问能删什么。

## 本机约定

- 路径写绝对路径或 `~/` 开头，写之前 `test -e`。
- 命令要能直接粘贴；没跑过的命令标「未验证」。
- 派单文档必填约束：删除走 `trash`，不用 `rm`。
- 台账类文档分两段：头部一屏的状态摘要，下面追加式记录。读者只读头部。
- 描述 agent 该读的历史会话时注明：`~/.dsh/sessions/*/session.v4.jsonl.zstd` 是压缩文件，搜内容先 `zstd -dc`。

## 写 skill 时

- 触发方式二选一：
  - 模型触发：保留 `description`，agent 可自己调用，其他 skill 也能引用。代价是描述行常驻上下文。描述写触发分支。
  - 用户触发：加 `disable-model-invocation: true`，只有人敲名字才触发。不占上下文，但人要记得它存在；描述改成一句人话摘要。
- 只会手动用的 skill 选用户触发。agent 必须自己找到、或别的 skill 必须调用，才选模型触发。
- 几个 skill 共用的参考：放进一个纯参考的模型触发 skill，或放到 skill 体系之外的普通文件，各 skill 用指针指过去。
- 用户触发的 skill 太多记不住，加一个路由 skill：列出其他 skill 和各自适用场景，只提示，不能触发。
- 新 skill 目录放 `~/xiebaiyuan-skills/skills/<name>/SKILL.md`，细节放 `references/`。

## 改已有文档

- 用标题当替换锚点时，替换内容里把标题带回去，否则标题消失，正文挂在上一节下面。编号步骤、表格前的引导行同理。
- 改之前重读当前文件。长会话里文件可能已被改过，按记忆里的文本匹配会失败，或静默匹配错位置。
- 主题已有文件就在里面加内容，不新建兄弟文件。一个事故一个文件，是沉积的另一种形态。

## 定稿自检

零命中是硬门槛，词表行本身豁免：

```
rg -n "不是.{0,20}而是|击穿|打穿|扛住|接住|拉齐|抓手|赋能|颗粒度|高负|微服|连池|闸门|夹具|核心洞察|关键设计|本质区别|值得注意的是|关键在于|综上所述|总而言之|进行[了]?(优化|分析|处理|调整)|的基础上|对于[^，。]{0,10}而言|被[^，。]{0,6}所" <文件>
```

完成标准：硬门槛零命中；每个分支有对应路径；每一步有可判定的完成标准；没有环境里查得到的复述。
